      🎓 Academic Project Guide, Mathematical Formulations & Viva Prep

      1. Problem Statement

      Modern electronic messaging (SMS, Email, Chat) is plagued by social engineering attacks, spoofed sender domains, and phishing links. Traditional keyword filters fail due to homoglyph obfuscation (e.g. Cyrillic lookalikes) and false-positive substring matches (e.g. *"winter"* triggering *"win"*). This project proposes an ensemble hybrid NLP architecture that combines probabilistic Bayesian inference, vector space cosine similarity, and deterministic threat heuristics.

      2. Mathematical Formulation 1: Naive Bayes Theorem

      Given a message represented as a feature vector of words \( W = \{w_1, w_2, \dots, w_n\} \), the posterior probability of being Spam is computed using Bayes' rule:

      $$P(\text{Spam} \mid W) = \frac{P(\text{Spam}) \prod_{i=1}^n P(w_i \mid \text{Spam})}{P(W)}$$

      To prevent underflow and zero-frequency errors, we apply Laplace Smoothing (\(\alpha = 1\)):

      $$\hat{P}(w_i \mid \text{Spam}) = \frac{\text{Count}(w_i, \text{Spam}) + 1}{\sum_{w} \text{Count}(w, \text{Spam}) + |V|}$$

      3. Mathematical Formulation 2: TF-IDF & Cosine Similarity

      Each document is represented in a multi-dimensional vector space using Term Frequency-Inverse Document Frequency:

      $$\text{TF-IDF}(t, d) = \text{TF}(t, d) \times \log\left(1 + \frac{N}{\text{DF}(t)}\right)$$

      The cosine angle between message vector \( \vec{q} \) and the spam centroid vector \( \vec{C}_{\text{spam}} \) measures semantic proximity:

      $$\text{Cosine Similarity} = \frac{\vec{q} \cdot \vec{C}_{\text{spam}}}{\|\vec{q}\| \|\vec{C}_{\text{spam}}\|}$$

      4. Common Viva Defense Questions & Model Answers

      Q: Why did you combine Heuristics with Machine Learning instead of using ML alone?

      A: Machine learning models rely purely on token probabilities. Attackers can bypass pure ML by crafting "Good Word Attacks" (padding phishing links with clean dictionary words). By combining heuristics (URL IP checks, brand typosquatting, SPF/DKIM validation) with Naive Bayes, the system catches structural threats that ML probabilities alone would miss.

      Q: What is the purpose of Laplace smoothing in your Bayes implementation?

      A: If a test message contains a word that never appeared in the training spam dataset, the raw probability \( P(w \mid \text{Spam}) \) would be 0. Because probabilities are multiplied together, a single zero would zero out the entire product. Laplace smoothing adds 1 to the numerator to ensure non-zero values.

      Q: How do you handle brand typosquatting like 'paypa1.com'?

      A: We maintain a registry of high-value targeted brands and calculate string similarity and character substitution mappings (e.g. '1' -> 'l', '0' -> 'o'). If a domain references a brand name combined with unauthorized prefixes like 'login' or 'verify', a high-risk penalty is assigned.
